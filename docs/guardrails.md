# ガードレール

この文書は、AIエージェントがこのリポジトリで守る安全境界を定義します。迷った場合は、速度よりも復旧可能性と透明性を優先してください。

## Hard Stops

ユーザーの明示的な承認なしに実行してはいけません。

| 操作 | 理由 |
|---|---|
| `terraform apply` | 実環境を変更する |
| `terraform force-unlock` | 共有state破損のリスクがある |
| `terraform plan -lock=false` / `terraform apply -lock=false` | stateロックを迂回する |
| `git push --force` | リモート履歴を破壊し得る |
| 機密情報のコミット | 認証情報漏えいにつながる |

## Approval Required

次の変更は、実装前に方針と影響をユーザーへ提示してください。

- `bootstrap/` 配下の変更
- IAM権限の拡張
- S3、DynamoDB、Cognito、KMS、Terraform state などの削除・置換
- dev/prod の両方にまたがる設計変更
- state move/import が必要になり得るリネームやモジュール再構成
- データ保持、ダウンタイム、認証・認可の境界に影響する変更

## Existing Changes

- 未コミット変更はユーザー作業として扱います。
- 依頼に無関係な差分を戻さないでください。
- 依頼対象と同じファイルに既存差分がある場合は、その内容を読んでから上書きを避けて編集してください。

## Terraform State Lock

ステートロックに遭遇した場合:

1. `-lock=false` で再試行しない。
2. `terraform force-unlock` を自動実行しない。
3. エラーに含まれる環境、Lock ID、Operation、Who、Created を読み取る。
4. 完了報告では `Blocked by state lock` として扱う。
5. ロックが停滞している可能性がある場合は、ユーザーに手動解除を依頼する。

ステートロックは調整上の問題であり、コード変更の失敗とは区別します。

## Secrets And Data

- シークレット、トークン、秘密鍵、パスワード、AWSアカウントIDをコード、コメント、ログ、ドキュメント例に書かないでください。
- PIIや生トークンを Lambda ログへ出力しないでください。
- サンプル値は明らかなダミー値を使ってください。
- 認証情報が必要な検証を実行できない場合は、未実行理由として報告してください。

## IAM

- 最小権限を原則にします。
- ワイルドカードアクションは避け、必要なアクションを列挙します。
- 可能な限りリソースARNを絞ります。
- `Condition` が有効なサービスでは、境界条件を検討します。
- CIやローカル検証を通すためだけに権限を広げないでください。

## Bootstrap

`bootstrap/` は通常のCI/CDで自動適用されません。変更する場合は次を明記します。

- なぜ bootstrap 変更が必要か
- どの環境またはロールに影響するか
- 手動で適用する必要があるコマンドや順序
- 適用しない場合に発生する制約

## Reporting

完了報告では、成功・失敗・未実行・ロックによるブロックを混同しないでください。未検証の項目を「問題なし」と表現してはいけません。
